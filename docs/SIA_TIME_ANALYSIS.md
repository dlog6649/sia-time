# SIA Time Analysis

이 문서는 `sia-time` 크롬 확장프로그램이 SIA groupware의 `인사/근태 > 근태현황 > 근무시간집계현황` 화면에서 어떻게 동작하는지 정리한 기술 분석이다. 코드 기준은 미승인 출장 보완 적용 후이며, 과거 출장 차감 수정 사례의 샘플 기준일은 2026-04-22다.

그룹웨어 동작의 확인 근거, 사용자 전제, 출장 날짜와 승인 상태에 따른 적용 범위는 [그룹웨어 동작과 계산 규칙](GROUPWARE_BEHAVIOR.md)을 참고한다.

## 개요

이 프로그램은 SIA 근태 화면의 HTML 표를 읽어 팝오버에 요약 정보를 표시한다. 자체 DB나 백엔드는 사용하지 않으며 그룹웨어 원본 표의 값을 변경하지 않는다.

주요 표시 항목은 다음과 같다.

- 총 근무일
- 남은 근무일
- 남은 재택근무
- 내 현황
- 요약
- 미달시간

핵심 구현은 [src/open-popover/index.ts](../src/open-popover/index.ts)에 들어 있다.

## 동작 구조

1. 사용자가 `근무시간집계현황` 메뉴에 들어간다.
2. 확장프로그램이 `#_content` iframe 내부의 표 로딩이 끝날 때까지 기다린다.
3. `#grid2` 세부 현황 표와 `#grid3` 요약 표를 읽는다.
4. 지난 출장 보완분과 계산용 미달시간, 오늘 이후 특이사항 차감분을 계산한다.
5. 팝오버를 만들어 요약 정보를 표시한다.

진입점은 `openPopoverWhenReady()`와 `buildPopover()`다. 그룹웨어 데이터를 서버 API나 결재 문서에서 별도로 조회하는 구조는 아니다.

## 데이터 소스

### 요약 표와 원본 미달시간

`summaryTableOrNull()`은 iframe 안의 `#grid3`를 읽는다. `lackTimes()`는 헤더에서 `미달시간` 열을 찾은 뒤 첫 번째 데이터 행의 `HH:MM`을 시·분과 총 분(`totalLackMins`)으로 변환한다.

이 값은 **원본 월 미달시간**이다. 앱이 월 소정근로와 일별 인정시간으로 월 전체 미달시간을 다시 합산하지는 않는다. 앱 안의 표시·계산에서는 아래 출장 보완분을 뺀 `getEffectiveLackMins()`를 사용한다.

### 세부 현황 표

`detailTableOrNull()`은 `#grid2`를 읽는다. 사용하는 열은 다음과 같다.

- `일자`: 근무일과 지난 날짜·오늘 이후 날짜 구분
- `출근시간`, `퇴근시간`: 출장일의 하루 구간 확장과 오늘 출근시간 조회
- `근태구분`: 지난 출장 보완 대상 구분
- `소정근로 인정시간`: 이미 월 집계에 반영된 시간으로 간주하는 값
- `특이사항`: 출장 시간 구간, 오늘 이후 차감 항목, 재택근무 횟수

결재 문서의 기안 상태를 직접 읽지는 않는다. 2026-10-29 사용자가 확인한 “출장 행의 근태구분 `정상`은 승인 완료”를 적용하고, 지난 출장 보완은 근태구분 공란에만 적용한다. 다른 상태도 보완 대상에서 제외한다.

일별 인정시간과 월 집계 반영분의 일치는 사용자 전제와 보관 샘플의 합계 일치에 근거한다. 모든 기안 상태에서 독립 검증한 일반 법칙으로 보지는 않는다.

## 근무일과 남은 시간

### 근무일 판정

`workingDayTrs()`는 일자 셀에 자식 요소가 없는 행을 근무일로 선택한다. 현재 화면의 휴일은 날짜를 빨간 글씨용 `span`으로 감싸므로 제외된다. 주말·휴일 판정은 이 표의 DOM 표시에 의존한다.

출장이나 휴가가 있다는 이유만으로 근무일에서 제외하지는 않는다.

### 오늘 포함 남은 근무일

`remainingWorkingDayTrs()`는 선택한 근무일 중 브라우저의 오늘 자정 이상인 날짜를 남긴다.

`parseDateText()`는 `YYYY-MM-DD`와 뒤에 요일 괄호가 붙은 형식의 연·월·일을 로컬 자정으로 구성한다. UTC 해석에 따른 날짜 이동을 피하고, 4월 31일처럼 실제로 없는 날짜는 제외한다.

- 오늘이 근무일이면 오늘도 포함
- 미래 근무일 포함
- 오늘보다 이전인 날짜 제외

`totalRemainingMins()`는 다음 식으로 기본 근무시간을 계산한다.

```text
남은 기본 근무시간 = 남은 근무일 수 × 8시간
```

여기에는 아직 휴가나 출장 등 특이사항이 반영되지 않는다.

## 지난 미승인 출장 보완

`getPendingBusinessTripMins()`는 다음 조건을 만족하는 행의 보완분을 합산한다.

1. `workingDayTrs()`에 포함된 근무일이다.
2. 날짜가 오늘 자정보다 이전이다. 오늘·미래·주말·휴일 행은 보완하지 않는다.
3. 출장 특이사항에서 시간 구간을 읽을 수 있다.
4. `근태구분`이 공란이다. `정상` 및 다른 상태는 제외한다.

필수 열이 없거나 계산에 필요한 시간 값의 형식을 해석할 수 없으면 보완하지 않는다. 근태구분 열 자체가 없는 것을 근태구분 공란으로 간주하지 않는다.

### 시간 구간 구성

같은 날의 모든 출장 시간 구간에서 가장 이른 시작과 가장 늦은 종료를 선택한다. 실제 출근이 더 이르면 시작을 넓히고 실제 퇴근이 더 늦으면 끝을 넓힌다. 출퇴근 중 한 경계가 비어 있으면 그쪽은 출장 경계를 사용한다. 공란이 아닌 출퇴근 값이 잘못된 형식이면 해당 날짜를 보완하지 않는다.

그다음 구간을 08:00~22:00으로 제한하고, 12:00~13:00과 겹치는 분만 점심으로 한 번 뺀다. 08:00~22:00은 2026-10-29 사용자 확인에 따른 인정 범위다.

```text
하루 시작 = min(가장 이른 출장 시작, 값이 있는 실제 출근)
하루 종료 = max(가장 늦은 출장 종료, 값이 있는 실제 퇴근)
인정 시작 = max(하루 시작, 08:00)
인정 종료 = min(하루 종료, 22:00)
점심 겹침 = max(0, min(인정 종료, 13:00) − max(인정 시작, 12:00))
계산한 하루 인정시간 = max(0, 인정 종료 − 인정 시작 − 점심 겹침)
```

출장 구간별 지속시간을 합산하지 않으므로 겹치는 구간을 중복 계산하지 않는다. 여러 출장 구간 사이의 공백도 하루 시작부터 종료까지의 구간에 포함된다. 하루 8시간의 상한은 없으며, 08:00~22:00 전체라면 점심을 뺀 13시간이다.

### 이미 인정된 시간 제외

일별 `소정근로 인정시간`이 공란이면 0분으로 처리한다. 값이 있으면 `HH:MM`의 지속시간으로 읽는다. 시 부분이 24 이상인 지속시간도 허용하며 분은 0~59여야 한다. 값이 있는데 형식이 잘못되었다면 해당 행의 보완을 건너뛴다.

```text
행별 보완분 = max(0, 계산한 하루 인정시간 − 일별 소정근로 인정시간)
지난 출장 보완분 = 대상 행의 행별 보완분 합계
```

예를 들어 하루 인정시간을 8시간으로 계산하고 일별 인정시간에 이미 6시간이 있다면 보완은 2시간이다. 일별 인정시간이 8시간 이상이면 보완하지 않는다. `정상` 행은 인정시간이 비어 있어도 대상에 포함하지 않는다.

## 계산용 미달시간과 내 현황

`getEffectiveLackMins()`는 원본 미달시간에서 지난 출장 보완분을 뺀다.

```text
계산용 미달시간 = lackTimes().totalLackMins − getPendingBusinessTripMins()
```

`getTotalSavingMins()`의 `내 현황` 계산은 다음과 같다.

```text
내 현황 = 남은 기본 근무시간
        − 계산용 미달시간
        − 오늘 포함 남은 근무일의 특이사항 차감분
```

양수는 `저축`, 음수는 `대출`이며, 0이면 저축한 시간이 없다는 문구를 표시한다. 계산용 미달시간을 0 이상으로 제한하지 않아 원본 미달시간을 넘는 출장 보완으로 생긴 여유도 `내 현황`에 반영한다.

이 공통 계산용 미달시간은 `내 현황`, 일반 `요약`, `미달시간` 문구, 마지막 근무일 퇴근 안내에 사용한다. 표시마다 원본과 보완값을 섞지 않는다.

## 오늘 이후 특이사항 차감

`significantLines()`는 각 행의 특이사항을 줄 단위로 나누고 공백과 빈 줄을 제거한다. `significantPolicies`는 위에서부터 처음 일치한 정책을 사용한다.

| 문자열 조건 | 시간 | 차감 여부 |
| --- | --- | --- |
| `재택근무`, `연차`, `휴가`, `공가`, `병가`, `휴직`, `결혼`, `회갑`, `출산`, `사망`, `탈상`, `예비군`, `훈련소`를 포함하거나 정확히 `기타` | 8시간 | 예 |
| `반차`, `건강검진`, `백신접종`, `기타(반일)`을 포함 | 4시간 | 예 |
| 앞선 조건에 해당하지 않고 `출장`으로 시작 | 미래 차감에 사용하지 않음 | 아니요 |
| 등록된 정책에 해당하지 않음 | 0시간 | 아니요 |

`shouldSubtractSignificantFromLackTime()`으로 차감 대상을 먼저 고른 뒤 `convertSignificantToMins()`로 환산한다. 오늘 이후 출장은 `subtractFromLackTime: false`로 계속 제외한다. **지난 날짜 출장의 미반영분을 더하는 보완과 오늘 이후 특이사항을 빼는 차감은 날짜와 부호가 다르다.**

출장 시간 파싱은 이제 지난 출장 보완 경로에서 사용한다. 예전 구현의 “출장 파싱 함수가 남아 있지만 호출되지 않는다”는 설명은 현재 구현 전체에 해당하지 않는다.

재택근무가 앱에서 8시간 차감 정책에 들어 있다는 사실은 그룹웨어의 유급휴가 분류를 뜻하지 않는다. 각 항목의 미래 월 집계 반영 시점은 별도 확인이 필요하다.

## 요약과 미달시간 문구

`summaryLabel()`의 일반식은 다음과 같다.

```text
하루 필요 근무시간 = (남은 기본 근무시간 − 내 현황) ÷ 남은 근무일 수
                  = (계산용 미달시간 + 오늘 이후 특이사항 차감분) ÷ 남은 근무일 수
```

남은 근무일이 0이면 이달 근무 종료 문구를 표시한다. 필요한 시간이 음수면 남은 근무시간이 없다는 문구를 표시한다. 일반식으로 표시하는 분은 기존 `timeText()` 규칙대로 반올림한다.

`lackTimeLabel()`도 계산용 미달시간을 사용한다. 0 이하라면 남은 근무시간이 없다는 문구를 표시한다.

남은 근무일이 1일이고 오늘 출근시간이 있으면 `clockOutTimeForLastDayOfMonth()`의 퇴근 안내를 우선한다. 실제 출근과 08:00 중 늦은 시작, 필요한 점심시간, 계산용 미달시간에서 0 이상인 부족분, 코어타임 종료 15:00을 반영한다. 계산용 미달시간이 음수여도 부족분을 음수로 더해 퇴근 시각을 앞당기지는 않으며, 저축 여유는 `내 현황`에 남는다.

## 2026-04-22 출장 차감 오류와 수정

### 당시 입력과 해석

[보관 HTML 샘플](../tests/fixtures/scratch_41.html)의 월 요약은 다음 관계를 만족한다.

```text
소정근로 171:00 − 근무시간 75:19 − 유급휴가 24:00 − 연차 04:00 = 미달시간 67:41
```

2026-04-22를 기준일로 두면 남은 근무일은 7일, 기본 근무시간은 56시간이다. 오늘과 다음 날에 각각 `출장(09:00 ~ 18:00)`이 있고 일별 인정시간은 비어 있다. 당시 분석은 이 합계 16시간이 월 미달시간에 선반영되지 않은 것으로 해석했다. 이 샘플에는 별도 기안 상태 정보가 없으므로 모든 결재 상태의 집계 규칙으로 일반화하지 않는다.

샘플의 휴가와 반차는 기준일 이전인 4월 13~16일에만 있다. 기존 분석에 있던 미래 휴가 선반영 설명은 가정이며, 이 샘플로 미래 휴가가 언제 월 집계에 반영되는지 증명할 수 없다.

### 수정 전후

[출장 제외 커밋 `5bb14c6`](https://github.com/dlog6649/sia-time/commit/5bb14c6463b60d94234e24dd50e5753d7e2ccf86) 전에는 오늘 이후 특이사항 차감에 출장 16시간까지 포함했다.

| 계산 | 수정 전 | 출장 차감 제외 후 |
| --- | --- | --- |
| 내 현황 | `56:00 − 67:41 − 16:00 = −27:41` | `56:00 − 67:41 = −11:41` |
| 요약 | `(67:41 + 16:00) ÷ 7일` | `67:41 ÷ 7일` |
| 요약 표시 | 하루 11시간 57분 | 하루 9시간 40분 |

당시 분석은 미달시간에 남아 있다고 해석한 출장 시간을 추가 차감하여 필요 근무시간이 늘어난다고 판단해 이 차감을 제거했다. 사용자는 수정 후 최종 요약의 문제가 사라졌다고 2026-10-29 확인했다.

새 보완 규칙은 지난 근무일만 대상으로 한다. 이 샘플의 두 출장은 오늘과 미래이므로 보완분이 0이며, `11시간 41분 대출`과 하루 `9시간 40분` 결과를 그대로 유지한다. 기존 미래 출장 차감 제외 정책을 되돌린 것이 아니다.

## 검증과 유지보수

[회귀 테스트](../tests/open-popover-regression.test.mjs)는 기존 샘플 출력과 빌드 결과의 정합성에 더해 지난 출장 보완의 계산 경계를 확인한다.

- 지난 날짜·오늘·미래와 근무일·휴일 구분
- 근태구분 공란만 보완하고 `정상`·그 밖의 상태·필수 열 누락은 제외
- 출퇴근 공란의 출장 경계 대체와 실제 출퇴근에 의한 확장, 잘못된 형식 제외
- 여러 출장 구간의 가장 이른 시작과 가장 늦은 종료, 인정 범위 제한, 점심 한 번 공제, 8시간 상한 없음
- 일별 인정시간 공란·부분 인정·이미 충분한 인정·형식 오류 처리
- 공통 계산용 미달시간의 표시 반영과 음수 미달시간의 여유 보존
- 2026-04-22 기존 출장 차감 수정 결과 유지

이 테스트는 앱의 계산을 검증한다. 그룹웨어의 실제 기안 완료 전후 집계 시점과 일별·월 집계의 일반적인 일치 여부를 직접 검증하지는 않는다.

표의 DOM과 텍스트가 바뀌면 계산이 영향을 받는다. 특히 `#grid2`, `#grid3`, 열 이름, 일자의 휴일용 자식 요소, 출장 문자열 형식, 시간 값 형식을 확인해야 한다. 개발 검증에서는 원본 미달시간, 행별 출장 보완분, 오늘 이후 특이사항 차감분을 나눠 계산하고 실제 표 값과 비교한다.

새 그룹웨어 관찰 결과는 [그룹웨어 동작과 계산 규칙](GROUPWARE_BEHAVIOR.md)에 날짜·근태구분·기안 상태·전후 표 값과 함께 기록한다. 사용자 전제를 관찰 사실로 바꿀 때는 그 근거도 함께 남긴다.
