# 그룹웨어 동작과 시아시간 계산 규칙

시아시간은 그룹웨어의 `인사/근태 > 근태현황 > 근무시간집계현황` 화면에 표시된 표를 읽는다. 표를 읽는 함수와 계산식은 [기술 분석](SIA_TIME_ANALYSIS.md)을 참고한다.

## 앱에서 확인한 계산 규칙

- 그룹웨어 요약 표의 월 `미달시간`을 읽는다. `내 현황`은 오늘을 포함한 남은 근무일에 하루 8시간을 곱한 값에서 월 미달시간과 대상 특이사항의 차감 시간을 뺀 값이다.
- 그룹웨어 세부 표에서 일자에 휴일 표기가 있는 행을 근무일에서 제외한다. 휴가나 반차는 특이사항에 따라 시간을 차감한다.
- 재택근무·연차·휴가 등의 8시간, 반차·건강검진 등의 4시간은 시아시간이 오늘 이후 특이사항에 적용하는 값이다. 각 항목이 그룹웨어 월 집계에 반영되는 시점과 분류는 별도로 확인해야 한다.

## 주간 보기

주간 보기는 현재 조회 월의 세부 현황 표 `#grid2`에 표시된 날짜를 월요일~일요일로 묶는다. 월 경계에 걸친 주는 실제 집계 날짜와 조회 범위를 표시한다. 사용자가 요청한 주간 목표는 그룹웨어가 표시한 근무일마다 8시간이다.

- 오늘까지의 일별 `소정근로 인정시간`을 합산하며 공란은 0분으로 처리한다. 출장과 재택근무도 일별 인정시간으로 집계한다.
- 근무일의 `근태구분`이 `정상`이면 특이사항의 연차, 휴가, 공가, 병가, 휴직을 8시간, 반차를 4시간으로 인정한다. 하루 휴가 합계는 최대 8시간이다. `정상`을 적용 기준으로 삼는 것은 보관 샘플에 근거한 앱의 정책이다.
- 오늘을 남은 근무일에 포함한다. 오늘 이후의 휴가는 미달시간을 줄이고, 종일 휴가일은 하루 평균 필요 근무시간을 계산하는 일수에서 제외한다.
- 집계에 필요한 열이나 셀이 없거나 오늘까지의 인정시간 형식을 해석할 수 없으면 주간 결과 대신 데이터 안내를 표시한다.

```text
주간 목표 = 조회 범위의 근무일 수 × 8시간
주간 미달 = max(0, 주간 목표 − 오늘까지의 인정시간 − 조회 범위의 휴가 시간)
주간 내 현황 = 오늘까지의 인정시간 + 지난 휴가 시간 − 지난 근무일 수 × 8시간
```

## 보관 샘플에서 확인한 값

2026-04-22를 기준일로 둔 [보관 HTML](../tests/fixtures/scratch_41.html)의 월 요약은 다음 관계를 만족한다.

```text
소정근로 171:00 − 근무시간 75:19 − 유급휴가 24:00 − 연차 04:00 = 미달시간 67:41
```

샘플의 휴가와 반차는 기준일 이전인 4월 13~16일에만 표시된다. 미래 휴가, 반차, 재택근무가 월 집계에 반영되는 시점은 미확인이다.

보관 화면의 일별 인정시간 합계는 월 근무시간과 같은 75시간 19분이었다. 4월 13~15일 리프레시휴가 행은 인정시간이 공란이었고, 4월 16일 오전반차 행은 인정시간이 4시간이었다. 네 행의 근태구분은 `정상`이었다. 이 주의 근무일 5일, 인정시간 9시간 9분, 휴가·반차 28시간을 적용하면 주간 미달의 기대값은 2시간 51분이다. 4월 10일 재택근무 행에는 인정시간 8시간이 기록되어 있었다.

새 관찰을 문서에 남길 때는 조회 시점, 대상 날짜와 특이사항, 일별 인정시간, 월 요약 값, 보관 샘플을 함께 기록한다. 코드에서 확인한 앱 계산과 샘플에서 관찰한 그룹웨어 동작을 구분한다.

## 구현 검증

TypeScript 빌드를 보관 화면에 적용해 월간 출력, 주간 전환, 월 경계 집계를 확인했다. 회귀 테스트는 서울과 로스앤젤레스 시간대에서 통과했다.
