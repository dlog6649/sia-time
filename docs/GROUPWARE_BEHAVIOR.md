# 그룹웨어 근태 집계와 시아시간 계산 규칙

시아시간은 그룹웨어의 `인사/근태 > 근태현황 > 근무시간집계현황` 표를 읽어 `내 현황`과 `요약`을 계산한다. 월 `미달시간`을 기준으로 **지난 근무일의 근태구분이 비어 있는 출장에서 미인정분을 보완**한다. 오늘 포함 남은 근무일의 휴가 등은 기존 정책대로 별도 차감하며, **출장은 이 미래 특이사항 차감에서 계속 제외한다.**

최종 정리일은 2026-10-29이며, 코드 기준은 미승인 출장 보완 적용 후다. 그룹웨어 동작, 사용자가 제공한 전제, 앱의 계산 규칙을 아래에서 구분한다.

## 확인된 내용과 근거

| 내용 | 근거와 범위 |
| --- | --- |

| 2026-04-22 기준 샘플의 오늘과 다음 날 출장에는 특이사항이 있고 일별 인정시간은 비어 있다. | [보관 HTML](../tests/fixtures/scratch_41.html)의 4월 22일과 23일 행. 기안 상태는 담겨 있지 않다. |

## 앱이 사용하는 값과 계산식

| 값 | 읽는 위치 또는 계산 방법 |
| --- | --- |
| 원본 월 미달시간 | `#_content` iframe 안 `#grid3` 요약 표의 첫 행에서 `미달시간` 열을 읽는다. 월 소정근로나 일별 인정시간으로 월 전체를 다시 합산하지 않는다. |
| 근무일 | `#grid2` 세부 표에서 일자 셀에 자식 요소가 없는 행을 선택한다. 현재 화면의 휴일 표기는 날짜를 빨간색 `span`으로 감싼다. |
| 남은 근무일 | 선택한 근무일 중 브라우저의 오늘 자정 이후 날짜를 센다. 오늘도 포함하며 출장이나 휴가가 있다고 근무일에서 제외하지 않는다. |
| 남은 기본 근무시간 | 남은 근무일 수 × 8시간 |
| 지난 출장 보완분 | 오늘보다 이전인 근무일 중 출장 특이사항이 있고 근태구분이 공란인 행에서, 계산한 하루 인정시간과 이미 반영된 일별 인정시간의 차이 중 양수만 합산한다. |
| 계산용 미달시간 | 원본 월 미달시간 − 지난 출장 보완분 |
| 오늘 이후 특이사항 차감분 | 오늘 포함 남은 근무일의 특이사항을 줄 단위로 읽고, 차감 대상으로 설정된 항목의 시간을 합산한다. 출장은 제외한다. |

```text
행별 출장 보완분 = max(0, 계산한 하루 인정시간 − 일별 소정근로 인정시간)
계산용 미달시간 = 원본 월 미달시간 − 지난 출장 보완분 합계
내 현황 = 남은 기본 근무시간 − 계산용 미달시간 − 오늘 이후 특이사항 차감분
```

`getPendingBusinessTripMins()`가 지난 출장 보완분을, `getEffectiveLackMins()`가 계산용 미달시간을 제공한다. `내 현황`, 일반 `요약`, `미달시간` 문구, 마지막 근무일 퇴근 안내는 이 공통 계산용 값을 사용한다. 화면의 원본 표나 그룹웨어에 저장된 인정시간은 변경하지 않는다.

`내 현황`은 양수면 저축, 음수면 대출이다. 계산용 미달시간이 음수가 되어도 0으로 잘라 저장하지 않아 보완 후의 여유 시간이 `내 현황`에 남는다. 부족시간 문구와 퇴근 안내에서 추가로 채워야 할 시간은 0 미만으로 표시하지 않는다.

일반적인 `요약`의 하루 필요 근무시간은 다음 식을 사용한다.

```text
하루 필요 근무시간 = (남은 기본 근무시간 − 내 현황) ÷ 남은 근무일 수
                  = (계산용 미달시간 + 오늘 이후 특이사항 차감분) ÷ 남은 근무일 수
```

위 요약식은 남은 근무일이 있고 필요한 시간이 음수가 아닌 경우에 적용한다. 남은 근무일이 0일이면 근무 종료 문구를 표시한다. 1일이고 오늘 출근시간이 있으면 계산용 미달시간의 부족분, 점심시간, 코어타임 종료 시각을 이용한 퇴근 시각 안내를 우선한다. 세부 구현은 [기술 분석](SIA_TIME_ANALYSIS.md)을 참고한다.

## 지난 미승인 출장의 보완 규칙

### 대상 행

다음 조건을 모두 만족해야 한다.

- 앱에서 근무일로 분류한 행이다. 휴일·주말 표기 행은 제외한다.
- 행의 날짜가 브라우저의 오늘 자정보다 이전이다. 오늘과 미래 출장은 보완하지 않는다.
- 출장 시간 구간이 특이사항에 있다.
- `근태구분`을 공백 제거한 값이 비어 있다. `정상`은 승인 완료로 보아 제외하고, 다른 상태도 보완하지 않는다.

근태구분 등 필수 열이 없으면 보완하지 않는다. 열 자체가 없는 것을 공란으로 간주하지 않는다. 일별 인정시간이 비어 있으면 0분으로 사용한다. 값이 있으면 `HH:MM` 지속시간으로 읽고, 시가 24 이상인 값도 허용하되 분은 0~59여야 한다. 값이 있는데 시간으로 해석할 수 없으면 해당 행을 보완하지 않는다. 결재 상태나 이미 반영된 시간을 추측하여 덮어쓰지 않는다.

일자는 `YYYY-MM-DD` 또는 `YYYY-MM-DD(요일)`에서 연·월·일을 읽어 브라우저의 로컬 날짜로 비교한다. 날짜만 있는 문자열을 UTC 시각으로 해석해 오늘을 과거로 오인하지 않으며, 존재하지 않는 날짜는 보완 대상에서 제외한다.

### 하루 인정시간 계산

1. 같은 날의 출장 구간들에서 가장 이른 시작과 가장 늦은 종료를 선택한다. 구간별 시간을 단순 합산하지 않는다.
2. 실제 출근이 출장 시작보다 이르면 시작을 그 출근 시각까지 넓힌다. 실제 퇴근이 출장 종료보다 늦으면 끝을 그 퇴근 시각까지 넓힌다. 출퇴근 경계가 없으면 해당 출장 경계를 사용한다. 공란이 아닌 출퇴근 값의 형식이 잘못되었다면 그날은 보완하지 않는다.
3. 시작과 끝을 인정 범위인 08:00~22:00 안으로 제한한다.
4. 제한한 구간과 12:00~13:00이 겹치는 분만 점심시간으로 한 번 공제한다.
5. 일별 인정시간과 비교해 아직 인정되지 않은 양수 차이만 보완한다. 하루 8시간을 상한으로 두지 않는다.

여러 출장 구간 사이에 공백이 있어도 가장 이른 시작부터 가장 늦은 끝까지의 하루 구간으로 계산한다. 따라서 이 규칙은 구간들의 합집합을 계산하는 방식이 아니다.

| 입력 예 | 하루 인정시간 | 일별 인정시간 | 보완분 |
| --- | --- | --- | --- |
| 출장 09:00~18:00, 출퇴근 없음 | 8시간 | 공란 | 8시간 |
| 출장 09:00~18:00, 실제 출근 08:00·퇴근 19:00 | 10시간 | 8시간 | 2시간 |
| 출장 09:00~18:00, 실제 출근 08:30·퇴근 19:00 | 9시간 30분 | 6시간 | 3시간 30분 |
| 출장 07:00~23:00, 출퇴근 없음 | 08:00~22:00에서 점심 공제한 13시간 | 공란 | 13시간 |
| 출장 09:00~18:00 | 8시간 | 9시간 | 0시간 |

위 예시는 대상 행 조건을 충족할 때의 계산 예다. `정상`이거나 오늘·미래·휴일인 행에는 적용하지 않는다.

## 오늘 이후 특이사항 차감 정책

아래 표는 [앱의 `significantPolicies`](../src/open-popover/index.ts)를 설명한다. 그룹웨어 내부의 집계 항목이나 인사 규정 분류를 의미하지 않는다. 정책은 위에서부터 처음 일치한 항목을 사용한다.

| 특이사항 문자열 조건 | 차감 시간 | 오늘 이후 차감 적용 |
| --- | --- | --- |
| `재택근무`, `연차`, `휴가`, `공가`, `병가`, `휴직`, `결혼`, `회갑`, `출산`, `사망`, `탈상`, `예비군`, `훈련소` 중 하나를 포함하거나 정확히 `기타` | 8시간 | 예 |
| `반차`, `건강검진`, `백신접종`, `기타(반일)` 중 하나를 포함 | 4시간 | 예 |
| 앞선 조건에 해당하지 않고 `출장`으로 시작 | 0시간 | **아니요** |
| 어느 정책에도 해당하지 않음 | 0시간 | 아니요 |

출장 시간 파싱은 지난 출장의 보완 계산에 사용한다. 하지만 오늘 이후 출장 항목은 `subtractFromLackTime: false`로 먼저 제외하므로 미래 특이사항 차감에는 계속 사용하지 않는다. 과거 코드에서 파싱 함수가 호출되지 않았다는 설명을 새 보완 계산 전체에 적용하면 안 된다.

## 미래 출장 차감을 제외한 이유

### 당시 샘플

2026-04-22를 오늘로 둔 [보관 HTML](../tests/fixtures/scratch_41.html)의 값은 다음과 같다. 이는 과거 샘플이며 현재 사용자의 근태 값이 아니다.

| 항목 | 값 |
| --- | --- |
| 월 소정근로 | 171시간 |
| 근무시간 | 75시간 19분 |
| 유급휴가 | 24시간 |
| 연차 | 4시간 |
| 월 미달시간 | 67시간 41분 |
| 오늘 포함 남은 근무일 | 7일 |
| 남은 기본 근무시간 | 56시간 |
| 오늘과 다음 날 출장 | 각각 `출장(09:00 ~ 18:00)`, 합계 16시간 |

샘플의 월 요약은 `171:00 − 75:19 − 24:00 − 04:00 = 67:41`이다. 출장의 일별 인정시간은 비어 있으며, 당시 분석은 해당 출장 시간이 미달시간에 선반영되지 않은 것으로 해석했다.

### 2026-04-22 수정 전후

수정 전에는 모든 특이사항을 보정 대상으로 삼아 출장 16시간도 `내 현황`에서 차감했다. 당시 분석은 이 출장 시간이 미달시간에 남아 있다고 해석했으므로, 추가 차감이 필요 근무시간을 불필요하게 늘린다고 판단했다.

| 항목 | 수정 전 | 출장 차감 제외 후 |
| --- | --- | --- |
| 오늘 이후 특이사항 차감 | 출장 16시간 | 0시간 |
| 내 현황 계산 | `56:00 − 67:41 − 16:00 = −27:41` | `56:00 − 67:41 = −11:41` |
| 내 현황 표시 | 27시간 41분 대출 | 11시간 41분 대출 |
| 요약 계산 | `83:41 ÷ 7일` | `67:41 ÷ 7일` |
| 요약 표시 | 하루 11시간 57분 근무 | 하루 9시간 40분 근무 |

[수정 `5bb14c6`](https://github.com/dlog6649/sia-time/commit/5bb14c6463b60d94234e24dd50e5753d7e2ccf86)은 시간 환산 전에 `출장`으로 시작하는 항목을 제외했다. [후속 정리 `139663a`](https://github.com/dlog6649/sia-time/commit/139663a7256c5593417056f7d1e4f6eaa09ed187)는 이를 `subtractFromLackTime: false` 정책으로 옮겼다.

이때 제거한 것은 **오늘 이후 출장을 추가 차감하는 동작**이다. 새로 추가한 지난 출장 보완은 이 차감을 다시 켜는 기능이 아니다. 기존 샘플의 두 출장은 오늘과 미래이므로 새 보완 대상에서도 제외되며, `11시간 41분 대출`과 하루 `9시간 40분`이라는 결과를 유지해야 한다.

## 출장 날짜와 근태구분에 따른 현재 처리

아래 표는 근무일로 분류된 날짜의 출장을 기준으로 한다. 앱은 별도 결재 문서의 상태 대신 세부 표의 근태구분을 사용한다.

| 상황 | 현재 앱의 처리 |
| --- | --- |
| 오늘 이후 출장, 근태구분 공란 | 남은 근무일에 포함한다. 지난 출장 보완과 오늘 이후 출장 차감을 모두 적용하지 않는다. |
| 오늘 이후 출장, 근태구분 `정상` | 동일하게 남은 근무일에 포함하고 출장 보완·차감을 적용하지 않는다. |
| 지난 출장, 근태구분 공란 | 계산한 하루 인정시간에서 일별 인정시간을 뺀 양수만 계산용 미달시간에서 공제한다. |
| 지난 출장, 근태구분 `정상` | 승인 완료로 보아 보완하지 않는다. 그룹웨어 원본 월 미달시간의 반영분을 그대로 따른다. |
| 출장 행의 근태구분이 그 밖의 값 | 지난 출장 보완을 적용하지 않는다. |

남은 근무일과 다른 보정값이 같다면 계산용 미달시간이 8시간 줄 때 내 현황은 8시간 올라간다. **미래 출장을 미리 인정해 원본 미달시간이 8시간 줄어드는 경우**에는 현재 계산이 그 미래 근무를 저축처럼 8시간 먼저 표시한다. 이는 계산식에서 도출되는 조건부 결과이며, 그룹웨어가 실제로 그렇게 동작한다는 관찰 결과가 아니다.

## 추가로 확인할 그룹웨어 동작

다음 항목은 아직 일반 규칙으로 확정하지 않는다.

- 기안 완료 후 일별 인정시간과 월 미달시간이 갱신되는 시점 및 새로고침이나 별도 집계의 필요 여부
- 일별 인정시간이 월 집계 반영분과 일치한다는 전제가 여러 기안 상태와 날짜에서도 성립하는지
- 기안 완료된 미래 출장의 인정시간과 월 집계가 출장 날짜 이전에도 반영되는지
- 미래 휴가, 반차, 재택근무가 어떤 월 요약 항목에 언제 반영되는지

기존 분석의 미래 휴가 선반영 설명은 당시 가정이다. 보관 HTML의 휴가와 반차는 기준일 이전인 4월 13~16일에만 있어, 이 샘플로 미래 휴가의 선반영을 증명할 수 없다. 재택근무가 앱에서 8시간 차감 대상이라는 이유만으로 그룹웨어의 유급휴가 항목에 집계된다고 해석해서도 안 된다.

## 계산 변경과 검증 기준

사용자에게 보여주는 현황과 요약은 명확해야 한다. 계산의 불확실성을 사용자가 판단하도록 요구하는 의심 표시나 잠정값 안내로 처리하지 않는다.

지난 출장 보완은 명시한 날짜·근무일·근태구분 조건과 유효한 시간 값으로만 계산한다. 값이 있는데 해석할 수 없는 일별 인정시간은 0으로 추측하지 않는다. 정책을 바꿀 때는 특이사항, 일별 인정시간, 근태구분, 월 요약 전체 값, 조회 시점을 함께 기록해 전제와 관찰 결과를 구분한다.

[회귀 테스트](../tests/open-popover-regression.test.mjs)에서 다음 시나리오를 검증한다. 이 테스트는 앱 계산을 확인하며 실제 그룹웨어의 결재·집계 동작을 검증하는 것은 아니다.

- 오늘·미래·휴일 출장 제외와 `정상`·기타 근태구분·필수 열 누락 제외
- 지난 근무일의 근태구분 공란에서 미반영분만 보완, 인정시간 공란은 0, 인정시간과 출퇴근의 형식 오류는 제외
- 실제 출퇴근에 의한 구간 확장, 08:00~22:00 제한, 점심 겹침 한 번 공제, 8시간 상한 없음
- 여러 출장 구간의 가장 이른 시작과 가장 늦은 종료 사용, 이미 인정된 시간의 중복 가산 방지
- 공통 계산용 미달시간이 내 현황·요약·미달시간 문구·마지막 날 퇴근 안내에 반영되는지와 음수 미달시간의 여유 보존
- 2026-04-22 기존 샘플의 내 현황과 요약 결과 유지

2026-10-29 구현 검증에서 `pnpm type`과 빌드를 포함한 `pnpm test`의 49개 테스트가 통과했다. 아래 시간대 검증도 4개 테스트가 통과해, UTC보다 서쪽인 환경에서 오늘 출장을 지난 출장으로 오인하지 않는지 확인했다.

```bash
TZ=America/Los_Angeles node --test --test-name-pattern 'today and future|invalid calendar' tests/open-popover-regression.test.mjs
```

새 관찰을 추가할 때는 관찰 날짜와 대상 근태 날짜, 기안 상태 또는 근태구분, 전후 표 값, 보관 샘플 또는 관련 커밋을 함께 남긴다. 가정이 확인되면 해당 설명을 관찰 결과로 갱신한다.
